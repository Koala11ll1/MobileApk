# Заробіток — віджет живого підрахунку зарплати

Android-віджет, який показує суму, що набігає за поточну зміну.
Час тікає щосекунди прямо на домашньому екрані, сума оновлюється раз на хвилину.
Усередині апки — повноцінний щосекундний лічильник.

## Як це працює

Ключове рішення: **сума ніколи не зберігається як накопичене число.**
У сховищі лежить лише час початку зміни і ставка, а сума — чиста функція:

```
сума = ставка / 3600 × оплачувані_секунди
```

Тому перезавантаження телефона, вбитий процес чи сплячий режим нічого не ламають:
при наступній перемальовці число перераховується від часу старту.

### Чому віджет не рахує сам

`RemoteViews` — це статичний знімок, який малює процес лаунчера.
Наш C#-код у ньому не виконується, таймера там немає.
Єдиний елемент, здатний тікати самостійно — стандартний `Chronometer`,
і він уміє показувати лише час.

Звідси архітектура:

| Що | Як оновлюється | Ціна |
|---|---|---|
| Час на віджеті | `Chronometer` тікає сам у лаунчері | 0 |
| Сума на віджеті | `AlarmManager`, 60 с, `ElapsedRealtime` без wakeup | ~0 |
| Сума при розблокуванні | `ACTION_USER_PRESENT` | 0 |
| Екран апки | `IDispatcherTimer`, 1 с | тільки поки апка відкрита |

`ElapsedRealtime` **без** `Wakeup` обрано свідомо: якщо екран вимкнено,
віджета ніхто не бачить, і будити пристрій немає сенсу.

### Що це дало

- Жодного foreground-сервісу і постійного сповіщення
- З дозволів потрібен лише `RECEIVE_BOOT_COMPLETED`
- **Samsung Device Care, Sleeping apps і Deep sleeping apps більше не проблема** —
  вбивати нічого, апка не тримає фонових процесів
- Немає ризику відмови в Google Play через `foregroundServiceType="specialUse"`

Компроміс один: цифра грошей стрибає раз на хвилину, а не пливе щосекунди.
При 100 ₴/год це крок 1.67 ₴.

## Збірка

Файли розраховані на стандартний шаблон MAUI — так вони отримають
іконку, сплеш і шрифти без зайвої мороки:

```bash
dotnet workload install maui
dotnet new maui -n ZarobitokApp
```

Далі скопіюй у створений проєкт вміст цієї теки, замінивши однойменні файли.
У `ZarobitokApp.csproj` перевір TFM: якщо в тебе .NET 9 — заміни `net10.0` на `net9.0`
(`dotnet --list-sdks` покаже версію).

Запуск на телефоні:

```bash
dotnet build -t:Run -f net10.0-android
```

### APK

```bash
keytool -genkeypair -v -keystore zarobitok.keystore \
  -alias zarobitok -keyalg RSA -keysize 2048 -validity 10000

dotnet publish -f net10.0-android -c Release \
  -p:AndroidPackageFormat=apk \
  -p:AndroidKeyStore=true \
  -p:AndroidSigningKeyStore=zarobitok.keystore \
  -p:AndroidSigningKeyAlias=zarobitok \
  -p:AndroidSigningKeyPass=ТВІЙ_ПАРОЛЬ \
  -p:AndroidSigningStorePass=ТВІЙ_ПАРОЛЬ
```

APK зʼявиться у `bin/Release/net10.0-android/publish/`.
Для Google Play прибери `AndroidPackageFormat=apk` — тоді збереться AAB.

## Керування

- **Віджет лише показує** суму і час. Він нічого не робить у відповідь на
  дотик: випадковий тап по домашньому екрану більше не може завершити зміну
- Керування зміною живе тільки в апці, на вкладці «Зміна»
- Чотири вкладки: «Зміна» (лічильник, старт/стоп, деталі), «Допзаробіток»
  (каталог типів на кшталт продажу з лічильником +/-), «Журнал» (збережені
  зміни, можна видалити помилкову), «Налаштування» (ставка, валюта,
  планові години, перерва, коефіцієнт)
- **Початок зміни можна пересунути** — і перед стартом, і під час зміни.
  Пікер дає лише час доби; якщо він сьогодні ще не настав, це вчора —
  так працює нічна зміна
- **Допзаробіток** — це каталог типів (`ExtraItem`: назва + ціна за
  одиницю), який живе постійно, і тіки (`ExtraTick`: +1/-1 з міткою часу)
  по кожному типу. Тип можна створити будь-коли; кнопки +/- активні лише
  під час зміни й рахують штуки для НЕЇ — на новій зміні лічильник завжди
  з нуля, бо це не збережене число, а сума тіків у її діапазоні
- Журнал завершених змін зберігається локально (останні 200) і
  показується згрупованим по днях (за днем ЗАВЕРШЕННЯ зміни) із
  підсумком за кожен день. Тап по зміні відкриває деталі дня: скільки
  годин, середня вартість години окремо по ставці й разом з допзаробітком,
  розбивка допзаробітку по видах — і, якщо за день рівно одна зміна,
  ті самі +/- для правки кількості заднім числом. Суми ніде не
  "запікаються" в момент зупинки зміни, тому редагування одразу
  перераховує день, тиждень і будь-який інший підсумок

## Структура

```
Models/ShiftState.cs                 стан зміни + запис журналу
Services/EarningsCalculator.cs       вся математика, без залежностей від платформи
Services/ShiftStore.cs               спільне сховище апки й віджета (SharedPreferences)
Services/ShiftManager.cs             старт/стоп, синхронізація віджета
Platforms/Android/EarningsWidget.cs  сам віджет (AppWidgetProvider)
Platforms/Android/WidgetScheduler.cs хвилинний будильник оновлення суми
Platforms/Android/BootReceiver.cs    відновлення розкладу після ребуту
AppTabs.cs                           чотири вкладки апки
Pages/ShiftPage.xaml(.cs)            лічильник, старт/стоп, деталі зміни
Pages/ExtrasPage.xaml(.cs)           додавання допзаробітку до поточної зміни
Pages/HistoryPage.xaml(.cs)          журнал по днях, видалення зміни
Pages/DayDetailPage.xaml(.cs)        деталі дня: години, середня ₴/год, допки
Pages/SettingsPage.xaml(.cs)         ставка, валюта, план, перерва, коефіцієнт
```

`EarningsCalculator` навмисно не знає нічого про Android — його можна
покрити юніт-тестами звичайним xUnit-проєктом.

## Перевірено

Формули прогнані на контрольних прикладах:
100 ₴/год за 8 год = 800 ₴; 10 год з коефіцієнтом 1.5 = 1100 ₴;
9 год мінус 30 хв перерви = 850 ₴.

Сам проєкт **не збирався** — у середовищі, де писався код, немає .NET SDK
і Android-інструментів. Дрібні правки під твою версію MAUI можливі.

## Windows

Android-специфічні файли ізольовані через `#if ANDROID`, а `ShiftStore`
на Windows падає назад на `Preferences`. Десктопна збірка покаже той самий
екран із лічильником, але без віджета — на Windows це інша підсистема.
